The 40 unresolved helpers in the previous core-library consumers are gone.
Both LLVM and trust-cg counting consumers now link to CG-built core and pass
11,465 UTF-8 character counts each. An expanded LLVM consumer passes 81,097
counting/UTF-8-validation cases against CG-built core. The expanded CG consumer
still fails to link because both it and core strongly define `str::as_bytes`,
a function rustc classifies as internal to its codegen unit. This is progress
in core-library use, not a completed sysroot rebuild.

The bridge now normalizes each MIR body with rustc's own monomorphized
reachability decisions before its control-flow and storage analyses. Constant
and runtime-check switches with one monomorphized successor become gotos;
unreachable blocks become empty unreachable blocks. Statements on live blocks
remain intact, and dynamic switches retain their successors. Bodies with no
changes are borrowed. This follows the same traversal used by the pinned
rustc item collector and LLVM backend, preventing calls to helpers rustc
intentionally never instantiates.

Direct calls resolving to `ShimKind::DropGlue(_, None)` branch to their
returning successor. Recognition uses the resolved instance identity, not a
function name or a superficial argument type. A non-returning empty-drop call
is refused. Indirect calls and real user destructors retain their normal
lowering. No linker stubs or missing-symbol substitutions are introduced.

The new maintained native regression passes **720,896 cases** over eight
LLVM/trust-cg executions at O0–O3 with `panic=abort`. It checks eight const
instantiations with nested switches, both runtime branches and callback
counts, no-op drops of words/slices/unit, reified drop calls, and a real
user destructor. The previous backend rejects the same final source with
three uncollected empty-drop-glue references. Boundary tests compile four
constant-dead cases with CG, retain refusals for eight live/dynamic assembly
cases, and accept all twelve LLVM twins.

The control invocation covers residual control flow, suffix searching, wide
overflow returns and zero-sized destructor behavior (including unwind), plus
existing refusal boundaries. It reports 6 passed and 1 failed, with no ignored
tests. The sole failure is mandatory machine-proof admission.

The expanded C driver has an independent UTF-8 validator. It tests every
pair of bytes, 4,096 generated byte strings of lengths 0–128, and 11,465
valid UTF-8 prefixes. It compares validity, the valid-prefix length and the
error length, including incomplete sequences. Character counting calls the
actual core body. The core archive and linked executable both define
`do_count_chars` (2,300 code bytes) and `str::converts::from_utf8` (568 bytes).
These tests use matching LLVM-built compiler-builtins; they are not a
CG-only sysroot or proof-qualified execution.

The earlier alloc summary counted only mangled function entries and omitted
`sync::STATIC_INNER_SLICE`, whose 16-byte alignment is unsupported by that
static emission path. Both baseline and current structured diagnostics have
148 roots. The new traversal adds no alloc roots and removes none. The
compiler-builtins and alloc census replays keep their prior dependency and
configuration pins, changing only the backend.

Two additional limitations were retained as raw probes. An O2 local
`ManuallyDrop<Guard>` projected raw-pointer shape is still refused; the
maintained destructor control uses ordinary `drop(Guard(value))` to test
whether a real destructor is preserved. The expanded CG consumer's duplicate
symbol is independently corroborated by `-Zprint-mono-items`: rustc labels
`str::as_bytes` internal, while the emitted objects expose strong global
copies. Neither limitation is claimed fixed here.
