# trust-cg-sat — v0.1.0 SAT-Competition 2026 system description

`trust-cg-sat` is an experimental SAT front end for trust-cg. The v0.1.0
package targets the SAT-Competition 2026 No-Limits (Sequential) submission
format; it is a research artifact, not a claim of state-of-the-art SAT
performance.

- Solver: `trust-cg-sat`
- Release: `v0.1.0`
- Author: Andrew Yates, independent
- Languages: Rust and vendored C
- License: Apache-2.0; vendored components retain their own licenses
- Source: <https://github.com/alabsystems/trust-cg>
- Submission target: Linux x86-64

## Release scope

The executable embeds a pinned copy of MicroSAT as its CDCL solver. A Rust
trampoline at MicroSAT's propagation call site can additionally compile and
run trust-cg Boolean constraint propagation (BCP) kernels.

The default is deliberately conservative: plain invocation uses native
MicroSAT and does not start the JIT. The JIT modes are experimental comparison
modes:

| Mode | Flag | Behavior |
|---|---|---|
| Native | none | MicroSAT is authoritative; no JIT kernel is built. |
| Shadow | `--shadow` | Native MicroSAT is authoritative; a JIT kernel runs for differential checking. |
| Primary JIT | `--primary-jit` | The JIT result may be surfaced where the integration's authority rules allow it. |

`--shadow` and `--primary-jit` are mutually exclusive. Both accept
`--jit-kernel scan`, `with-decisions`, or `watched-literal`; the default is
`watched-literal`.

## Architecture

```text
DIMACS CNF
    |
    v
vendored MicroSAT parser and CDCL state
    |
    v
propagation trampoline
    |-- native MicroSAT propagation
    `-- optional trust-cg JIT BCP kernel
            |
            `-- shadow comparison or primary-JIT authority gate
```

Even in primary-JIT mode, native propagation still executes where MicroSAT
state must be mutated for its trail, reasons, learned clauses, and conflict
analysis. Consequently, v0.1.0 does not describe primary-JIT mode as a
complete replacement for the native C propagation path.

## Verification and evidence boundary

The experiment exercises trust-cg's proof-aware IR and code-generation
pipeline, but the release claim is narrower than “a formally verified SAT
solver.”

| Component or result | v0.1.0 evidence | Boundary |
|---|---|---|
| MicroSAT parsing and CDCL | Native implementation plus tests | The C solver and its algorithms are not formally verified. |
| JIT BCP code generation | trust-cg host-JIT validation path | Coverage is target- and configuration-dependent, not an end-to-end theorem about the solver. |
| Native/JIT agreement | Differential counters and corpus tests | Agreement on a finite corpus is testing evidence, not a proof for all CNFs. |
| UNSAT results | DRAT output checked by the pinned drat-trim in the corpus test | This checks the exact proof-producing runs only; drat-trim remains in the trusted toolchain. |
| SAT results | Solver verdict and printed model | v0.1.0 makes no claim of an independent model checker in this package. |

On the release's Linux x86-64 target, the host-JIT configuration selects the
cached verification path. AArch64 host JIT currently selects unchecked
validation. Supported lowerings, the validator, solver, runtime, operating
system, hardware, and build toolchain remain part of the trusted or unverified
base. See [LIMITATIONS.md](LIMITATIONS.md) for the project-wide boundary.

## Input and output contract

The direct executable accepts:

```text
trust_cg_sat [OPTIONS] <instance.cnf> [proof.drat]
trust_cg_sat [OPTIONS] <instance.cnf> --proof <proof.drat>
```

It reads uncompressed DIMACS CNF. `.cnf.gz` input is not supported. Output
uses standard SAT competition lines:

- `s SATISFIABLE` plus `v` model lines, exit code 10
- `s UNSATISFIABLE`, exit code 20
- `s UNKNOWN`, exit code 0

Passing a proof path enables DRAT output. `--quiet` suppresses informational
`c` lines; `--verbose` enables JIT diagnostics.

## In-tree corpus

The release corpus contains 27 fixtures: 22 UNSAT and 5 SAT. It covers adder
equivalence, blocks-world planning, parity, pigeonhole, queens, and random
3-SAT families. Every fixture is deterministically generated by the project;
no SATLIB or AIM instance bytes are distributed. The authoritative fixture
list, expected verdicts, and provenance are in
[`corpus.json`](crates/trust-cg-sat-host/tests/fixtures/sat_corpus/corpus.json).

The corpus test checks every expected verdict. For each UNSAT fixture it passes
the emitted DRAT artifact to the vendored drat-trim binary and requires
acceptance; non-empty artifacts also receive a line-shape sanity check. A
primary-JIT corpus test checks verdict agreement and requires zero recorded
divergences.

This small, repository-sized corpus is a regression and differential-testing
set. It is not representative of the full SAT-Competition benchmark suite and
must not be used to infer competition ranking.

## Build and run

On a compatible Linux x86-64 host, a release checkout can build the StarExec
layout directly:

```sh
./starexec_build
./starexec_run_default.sh instance.cnf /tmp/trust-cg-sat
```

`starexec_build` uses the lockfile and writes `bin/trust_cg_sat`. The run
wrapper writes `/tmp/trust-cg-sat/proof.drat` for an UNSAT run.

The supported cross-host reproduction path is the Linux x86-64 Docker image,
with the source ref pinned to the release tag:

```sh
docker build --platform=linux/amd64 \
  --build-arg TRUST_CG_REF=v0.1.0 \
  -f docker/sat-comp-2026/Dockerfile \
  -t trust-cg-sat:0.1.0 .

mkdir -p proofs
docker run --rm --platform=linux/amd64 \
  -v "$PWD:/work" \
  trust-cg-sat:0.1.0 \
  /work/instance.cnf /work/proofs
```

The Dockerfile clones the requested trust-cg ref, builds with the pinned Rust
toolchain and `Cargo.lock`, and installs the wrapper and executable. Its final
stage is Ubuntu 24.04 because the produced executable is dynamically linked
against glibc; it is not advertised as a portable static binary.

## Release checks

From the repository root:

```sh
cargo test --locked -p trust-cg-sat-host --test trust_cg_sat_cli
cargo test --locked -p trust-cg-sat-host --test sat_corpus
```

The corpus test can take several minutes on slower hosts. Docker availability
and host emulation performance are environmental and are not implied by the
Rust test results.

## Limitations

- Native MicroSAT, not the JIT, is the default and remains the integration's
  load-bearing state machine.
- The solver is an intentionally small research host rather than a modern
  production SAT engine.
- The checked corpus is finite and small.
- Proof checking covers emitted UNSAT certificates, not SAT models or the
  whole compiler and solver stack.
- Validation guarantees depend on the selected architecture and configuration.
- v0.1.0 publishes no headline end-to-end speedup claim.

Methods and performance-claim status are in the
[v0.1.0 SAT/BCP benchmark report](benchmarks/benchmark_study.md).
