# trust-cg SAT/BCP benchmark report — v0.1.0

This report defines the public SAT/BCP evidence for trust-cg v0.1.0. It
describes the current corpus, correctness checks, and benchmark programs in
the release tree. It does not promote a headline speedup.

## Release claim status

| Question | v0.1.0 status |
|---|---|
| Is `trust_cg_sat` faster than native MicroSAT end to end? | No release claim. |
| Does JIT shadow mode agree with native MicroSAT on every CNF? | The corpus test and benchmark counters check a finite in-tree set; this is not a universal proof. |
| Are UNSAT outputs independently checked? | The corpus test requires a DRAT proof and acceptance by the pinned vendored drat-trim for each UNSAT fixture. |
| Is the SAT solver formally verified? | No. MicroSAT and the integration remain outside an end-to-end proof. |
| Are kernel-only timings end-to-end solver timings? | No. They answer a narrower code-generation question. |

No current, clean, release-designated timing artifact is committed for the
v0.1.0 SAT corpus. Consequently, this report gives commands and interpretation
rules rather than copying numbers from older development runs.

## Historical retraction

An earlier development draft reported a 6.1× end-to-end result on
`php-10-9.cnf`. That result used an older analyze-driver-force (ADF)
integration that later exhibited incorrect behavior on part of the corpus. It
is withdrawn and is not v0.1.0 evidence.

There is no substitute aggregate performance number in this release. A future
claim must come from the current tree, preserve per-fixture output, pass all
verdict, DRAT, and divergence checks, and include enough provenance to rerun
the measurement.

## Corpus

[`corpus.json`](../crates/trust-cg-sat-host/tests/fixtures/sat_corpus/corpus.json)
is the source of truth for correctness testing. At v0.1.0 it lists 27 DIMACS
fixtures: 22 UNSAT and 5 SAT.

| Family | Fixtures | SAT | UNSAT |
|---|---:|---:|---:|
| Adder equivalence | 2 | 0 | 2 |
| Blocks-world planning | 1 | 1 | 0 |
| Parity | 3 | 0 | 3 |
| Pigeonhole | 6 | 0 | 6 |
| Queens | 3 | 2 | 1 |
| Random 3-SAT | 12 | 2 | 10 |
| **Total** | **27** | **5** | **22** |

The manifest records provenance and expected verdicts. Every fixture is
deterministically generated by the project-authored `generators.py`; no
SATLIB or AIM instance bytes are distributed. The set is deliberately small
enough to ship in the repository. It is useful for regression and differential
testing, but it is neither a random sample nor a representative slice of the
full SAT-Competition corpus.

The standalone timing program discovers every `.cnf` file in the same
directory rather than reading the manifest. Before publishing a run, confirm
that its fixture count still matches the manifest.

## Correctness and checker gate

Run correctness checks before collecting or interpreting timings:

```sh
cargo test --locked -p trust-cg-sat-host --test trust_cg_sat_cli
cargo test --locked -p trust-cg-sat-host --test sat_corpus
```

The corpus test performs these checks:

1. Native MicroSAT returns the manifest's SAT or UNSAT verdict for every
   fixture.
2. Every UNSAT fixture writes a DRAT artifact; non-empty artifacts receive an
   additional line-shape check before replay.
3. The vendored drat-trim accepts each `(CNF, DRAT)` pair.
4. The primary-JIT corpus path returns the expected verdicts, records no
   native/JIT divergence, and exercises at least one primary return.

A failed, skipped, or timed-out gate invalidates performance conclusions from
that tree. SAT fixtures do not currently pass through an independent model
checker in this test, so the checker claim is limited to UNSAT DRAT output.

## Measurement programs

The repository exposes three complementary surfaces:

| Program | Scope | Important detail |
|---|---|---|
| `satlib_bench_table` | End-to-end parse and solve across every in-tree CNF, including native, shadow, primary-JIT, and cache variants | The legacy executable name is retained for compatibility; it consumes the project-authored release corpus. Prints arithmetic means over the requested repetitions; `--warmup` adds one untimed run. |
| `satlib_jit_shadow_bench` | Criterion groups for native solve, JIT-shadow solve, and JIT compile-only | The legacy benchmark name is retained for compatibility. Shadow measurements reset the JIT state so compilation remains visible and assert zero divergence. |
| `microsat_c_o3_baseline_bench` | Per-propagation comparison on a selected five-fixture subset | Compares MicroSAT C built at release optimization with Rust and fixed/chunked JIT kernels; this is not a whole-solver result. |

### Environment record

Capture this beside every result:

```sh
git rev-parse HEAD
git status --short
rustc -vV
cargo -V
uname -a
```

Also record CPU model, available memory, power mode, container or emulation
status, all `TRUST_CG_*`, `TCG_*`, and `XDG_CACHE_HOME` values, and whether the
host was otherwise idle. Results from a dirty tree can be useful during
development, but they must be labeled as such.

### End-to-end table

The following captures the current raw tables and diagnostics while isolating
the JIT disk-cache experiments from the user's normal cache:

```sh
report_dir="${TMPDIR:-/tmp}/trust-cg-sat-v0.1.0"
mkdir -p "$report_dir/cache"

XDG_CACHE_HOME="$report_dir/cache" \
  cargo run --release --locked -p trust-cg-sat-host \
    --bin satlib_bench_table -- --repetitions 10 --warmup \
    >"$report_dir/satlib-tables.md" \
    2>"$report_dir/satlib-diagnostics.txt"
```

Keep both files. Standard output contains per-fixture Markdown tables for
native versus shadow execution, in-memory and disk-cache cold/warm paths, and
primary-JIT variants. Standard error contains progress, fixture buckets,
amortization summaries, return telemetry, and divergence totals. Depending on
the host and the larger fixtures, a ten-repetition run can take several
minutes.

### Criterion runs

```sh
cargo bench --locked -p trust-cg-sat-host \
  --bench satlib_jit_shadow_bench

cargo bench --locked -p trust-cg-sat-host \
  --bench microsat_c_o3_baseline_bench
```

Criterion writes detailed estimates under `target/criterion/`. Preserve that
directory or its exported report together with the environment record.

## How to interpret the comparisons

- Native mode is the release default. It runs trampolined MicroSAT without
  building a JIT kernel.
- Shadow time includes native solving plus snapshot, JIT compilation and
  differential work. It measures the cost of checking, not replacement speed.
- Primary-JIT mode still invokes native propagation where MicroSAT state
  mutation is load-bearing. Its wall time must not be presented as a pure JIT
  replacement measurement.
- Cold and warm cache rows answer different questions. Never combine them in
  one aggregate or omit the cache state from a label.
- Compile-only results exclude solver search. Per-propagation results exclude
  most end-to-end work. Neither supports a whole-solver speed claim by itself.
- The MicroSAT per-propagation branch can perform conflict analysis and clause
  insertion on conflicts, while the kernel-only branches have a narrower unit
  of work. Compare conflict rows with that asymmetry stated.
- `-march=native`, host architecture, CPU frequency policy, and emulation can
  materially change results. Docker/QEMU is appropriate for build and
  functional reproduction, not for performance claims about a native
  SAT-Competition host.
- Mean values from `satlib_bench_table` should be accompanied by repetition
  count and, for a public claim, the individual samples or a spread measure.
  Small ratios inside run-to-run noise are parity, not wins.

## Minimum publication record

A future result cited from this study should include:

- full trust-cg revision and clean/dirty state;
- Rust version, target triple, OS, CPU, memory, and power/load conditions;
- exact command, flags, kernel choice, repetitions, warmup, and cache state;
- every per-fixture row, not only selected wins or a geomean;
- native and candidate verdicts, divergence count, and DRAT-checker outcome;
- compile time separated from solve time where the comparison requires it;
- failures and missing fixtures retained in the report; and
- raw stdout, stderr, and Criterion artifacts needed to audit the summary.

For solver architecture, CLI, packaging, and verification boundaries, see the
[SAT-Competition system description](../satcomp_2026_system_description.md).
Project-wide caveats are collected in [LIMITATIONS.md](../LIMITATIONS.md).
